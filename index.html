01 · What it is

Not an emulator

An emulator reads the game's MIPS instructions and interprets or JITs them while it runs. Static recompilation does that work once, ahead of time.

The game's functions become native code compiled into your binary, and there is no interpreter in the loop. What that code still needs is everything the game used to call into on real hardware.

That is fn64. It does not read your ROM's instructions at runtime; it answers the calls the recompiled code makes — the scheduler, message queues, timers, DMA, save, input and audio.

You supply
A ROM you own + N64Recomp output, or nothing.
fn64 supplies
The runtime those functions call into, the render seam, and the checks that grade it.

03 · Stages

Five stages. Each writes a file you can look at.

Discover, Recompile, Execute, Present, Prove. Re-run one without rebuilding the others. Hue encodes stage — the same color follows each stage everywhere on this page.

Discover

Recover function & section metadata from a local ROM.

Recompile

Emit native code — no interpreter in the loop.

Execute

Run under the typed runtime; unknowns trap loudly.

Present

Draw through the render seam to reference or RT64.

Prove

Grade the result against named evidence gates.

06 · Method

Built with AI, held to proof.

Most of this code is written by AI agents in orchestrated waves. A software engineer with 30 years of experience directs the work and reviews and merges every change. AI contributions are welcome — humans and agents follow the same contract (AGENTS.md), written from first-hand debugging, public docs and MIT source, never GPL code.

Strong types TRAPS LOUDLY

Typed Rust runners. Unknown behavior traps loudly instead of returning a plausible zero — past the implemented edge, the runtime names itself rather than guessing.

Behavioral test suite ASSERTS BEHAVIOR

Where other N64 projects verify correctness mainly by byte-matching the original ROM at build time, fn64 also carries a behavioral test suite that asserts the recompiled output behaves correctly.

Determinism bar CONSECUTIVE CLEAN RUNS

A deterministic fix needs 10 consecutive clean runs before it counts. A concurrency fix needs 20+.
