Run your recompiled ROM as a native app.

fn64 is a Rust runtime for Nintendo 64 static recompilation. Your recompiled ROM calls into it for the scheduler, message queues, timers, DMA and overlay lifecycle, save, input and audio.

  • Boots Ocarina of Time today
  • Pre-alpha
  • MIT OR Apache-2.0

Run it

The shell builds without any game content. It refuses to open an empty window and tells you what it needs instead.

Without a ROM

cargo run -p fn64-shell -- --demo

Drives the real window, framebuffer conversion and overlay from a synthetic RDRAM field, so the UI stack stays verifiable in a checkout with nothing to boot.

With your own ROM

RECOMPILED_DIR=.../OOTU/RecompiledFuncs \
ROM=.../oot-ntsc-1.0.z64 \
cargo run -p fn64-shell

Same intake contract as examples/oot-boot. This repository holds tooling and runtime code: no game assets, no ROM bytes, no recompiled game output. Everything derived from your ROM stays on your disk.

Discovery

fn64-discover reads a local ROM and recovers function and section metadata. You do not need a finished decomp to start.

Boot-bank function recovery, graded against public decomp answer keys. August 2026.

Wrong is zero on every title. Missing a function costs you work. Claiming a boundary that is not there costs you a debugging session. Graded, not blind: each run uses a donor ROM and an answer key from an existing decomp project, so cold-start discovery on an unstudied ROM is still the open frontier.

Stages

Each stage writes a file you can look at, so you can re-run one without rebuilding the others.

Discover
Analyze a local ROM, retain proven facts, keep a named blocker on every unresolved bank.
Recompile
Turn MIPS functions into typed Rust runners, one native function per MIPS function.
Execute
Link recompiled code to a clean-room Rust implementation of the runtime surface.
Present
Graphics, audio, input and platform integration through explicit backend seams.
Prove
Grade ABI shape, code generation and deterministic behavior with executable checks.

Crates

One workspace, separate crates, each publishable on its own. If you only want the ABI surface, you only take fn64-abi.

fn64-runtime
Scheduler, OS message queues, timers, PI/SI/VI/AI plumbing, rdram model, overlays.
fn64-abi
The extern "C" surface recompiled code links against.
fn64-shell
The executable: window, input, audio out, ROM intake.
fn64-discover
ROM discovery: symbol and section metadata without a decomp.
fn64-cpu-runtime
Linked typed execution runtime for generated VR4300 Rust runners.
fn64-render
Backend-neutral render seam and ordered microcode admission.
fn64-diff
The first-divergence comparator. Pure, no I/O.

What you can check

Four things in the repo you can run or read if you want to disagree with us.

c_smoke
Link-tests the ABI with a real C caller against the static library.
Instruction oracles
Generated callable bodies diffed against N64Recomp output, instruction by instruction.
scripts/lane-parity.sh
Audits whether the two generated callable-body sets agree.
docs/ROADMAP.md
Every known gap, named. Unimplemented behavior traps instead of returning zero.

A deterministic fix needs 10 consecutive clean runs before it counts. A concurrency fix needs 20 or more.

Status

Ocarina of Time boots in a windowed app with the RT64 renderer and working input. Audio is still broken (R5) and the outdoor gameplay eye-gate is unmet (R3b). Both are tracked in the roadmap.

Most of the code is written by agents in orchestrated waves, and a human reviews and merges every change. Both work from the same AGENTS.md: written from our own debugging, public documentation and MIT source, never from GPL code.
